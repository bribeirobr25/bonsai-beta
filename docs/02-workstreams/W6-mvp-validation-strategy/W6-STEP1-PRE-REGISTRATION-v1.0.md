# W6 · Step 1 Pre-Registration v1.0 — One-Tree Dedicated Value

**Frozen:** 5 September 2026, **before any participant contact.**
**Tests:** W4 `L2` · W2 `G1` + `G2` · W3 `Progress → Memory`

> **No threshold in this document may change after outcomes are visible.**
> (W4 standing rule; W2 `MIXED`/`FAIL` bands are theirs, not invented here.)

---

## 1. Hypothesis

> An expanding grower who already has a good-enough recording system can get
> enough incremental value from **one** tree to voluntarily add a second, before
> being asked to migrate a collection.

The load-bearing behaviour is **voluntary expansion after one-tree value** —
not satisfaction, not intent.

## 2. Eligibility

- approximately **5+ trees**
- currently uses at least one of: Photos, spreadsheet, notes, paper, dedicated tracker
- enough existing history on **one** selected tree to support a real retrieval task

**Do not mix first-tree owners into this result.** They are Step 2.

**Target: 8 participants** (W4 F0 floor).

## 3. Design — two stages, deliberately separated

### Stage A · concierge conversion — *value ceiling*

Participant picks **one tree that matters to them**. The researcher assembles
that tree's existing material into a compact chronological record in the
instrument. **The researcher does most of the assembly.**

The question this isolates:

> **Is the resulting object meaningfully better than their current workaround
> when migration effort is temporarily removed?**

If the answer is no *even under these conditions*, there is no reason to test
bulk migration.

### Stage B · burden restoration — *the real test*

After delivery: the participant gets the same instrument to add **another tree**.
**No migration request. No completion target. The researcher does not assemble
the second tree.**

## 4. Pre/post retrieval task

Before Stage A, ask the participant to perform one real task **in their current
system**:

- find the earliest photo of the selected tree
- find or estimate the last repot/intervention
- show progression between two periods

Record: **time · uncertainty · number of tools or places searched · their own
description of effort.** Repeat an equivalent task after Stage A.

This is a **value-ceiling probe, not a fair product benchmark.** If a curated
record creates no retrieval or progression advantage, the dedicated thesis is
weaker regardless of how the instrument feels.

## 5. Primary endpoint

Within **7 days** of receiving the one-tree record, **without a migration
prompt**:

> `voluntary_second_tree_addition_or_request`

Stronger variant: `participant_self_adds_second_tree`.

Also record whether they **return to the workaround instead**.

## 6. Decision rules — frozen

### F0 · existence screen (W4), n≈8

**Value-ceiling gate**
- **0–1** find a concrete retrieval/progression advantage even after concierge assembly → **`KILL / PARK L2`**
- **≥2** → proceed to expansion gate

**Expansion gate**
- **≥2** independent self-additions or explicit unprompted requests → **`SURVIVES CHEAP FALSIFICATION`**
- **1** → `MIXED`
- **0** → **`KILL L2 as land-and-expand`**, even if the object is liked

> *"I would add the rest later"* without doing so **does not count.**

### F1 · economic confirmation (W2) — only after F0 survives, protocol aligned with W2 first

- **`G1` STRONG:** ≥50% continue the dedicated workflow **without prompting** through the window **and** ≥30% make a meaningful real workflow shift
- **`G2` STRONG:** ≥50% experience a differentiated current-value event within 7 days **and** ≥40% voluntarily return for current utility

`MIXED` and `FAIL` bands are W2's. **W6 does not invent missing bands.**

## 7. What does not count as a pass

- creating a record while the researcher watches
- returning because we asked
- saying the concept is useful without reopening it
- expansion that happens **only** with concierge help → `MIXED · CONCIERGE VALUE`, not a pass

## 8. Controls

- the participant's **existing system stays available throughout** — this is the comparison
- recruitment source recorded; **recruitment is not Growth evidence**
- guided actions logged **separately** from spontaneous actions
- no reminders, care advice, AI or comparable-journey features in the instrument
- instrument break or eligibility violation → **`INVALID`, not `FAIL`**
- contradictory outcomes are **not overwritten** — durable use and abandonment can both be true

## 9. Diagnostic outcomes — all four are informative

| | Reading |
|---|---|
| **A** no incremental value | Photos/Excel/notes remain sufficient for this segment |
| **B** value exists, expansion does not | one-tree value is real; **migration/capture burden blocks it** |
| **C** expansion only with concierge | proposition may survive; **operational burden unresolved** |
| **D** voluntary expansion | survives to F1 — **does not prove sustainable logging** |

## 10. Non-generalization

Does **not** validate: people who do not already record · full-collection
completion · long-term logging retention · WTP · user-to-user growth · beginners.
