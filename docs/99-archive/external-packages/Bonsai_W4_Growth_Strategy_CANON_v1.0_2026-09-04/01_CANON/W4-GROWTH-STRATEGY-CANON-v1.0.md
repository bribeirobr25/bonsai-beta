---

## 0. Mandate

W4 exists to answer:

> **How could this venture plausibly find, activate and propagate through relevant users, and which Growth mechanisms also produce useful evidence?**

W4 does **not** begin with Instagram, TikTok, SEO or paid acquisition. It begins with:

`moment → actor → action → perceived value → possible loop → evidence generated`

The workstream is validation-first. At this stage, a mechanism that creates users **and** resolves a strategic uncertainty is more valuable than one that merely creates traffic.

---

## 1. Canonical evidence discipline

Every material claim must preserve the project taxonomy:

- `OBSERVED` — directly found in real evidence.
- `SUPPORTED SIGNAL` — consistent evidence exists, prevalence/strength unresolved.
- `CONTRADICTED` — evidence exists against the claim.
- `UNVALIDATED` — the required test has not been run or cannot currently be run.
- `DEFERRED` — deliberately not being tested now.

Two additional W4 operational labels are allowed when the underlying test has run:

- `PARTIALLY SUPPORTED / ... UNVALIDATED`
- `MIXED · <named risk>`

A blocked test is never a failure. A promising narrative is never evidence.

## 3. Current Growth thesis

The strongest current W4 thesis is not “make a viral bonsai app”. It is:

> **Find moments in which a grower already experiences a real job or switching pressure; deliver current value before migration/repeated logging dominates; then test whether the resulting tree-centred object or actor relationship can create a next action, a next user, or better evidence.**

Three consequences follow.

### 3.1 Acquisition is not activation

A signup, import or tree creation is not Growth success. If the user never experiences differentiated value, acquisition only accelerates churn.

### 3.2 Propagation is not sharing

A Journey being viewed or shared is not a Growth loop. Propagation requires a recipient to take meaningful next action.

### 3.3 Distribution advantage is not retained value

Mirai demonstrates that inherited audience can create much stronger observable distribution. Canon also contains a user replacing Mirai My Trees with Excel/folders. Therefore:

> **distribution advantage ≠ retained differentiated value.**

## 4. Main shared gate

The principal joint participant gate across W2/W3/W4 is:

> **Can a dedicated experience for one real tree generate current, differentiated value over Photos / Excel / notes before requiring collection migration or historical accumulation?**

This maps to:

- W4 `L2 · One-Tree Land-and-Expand`;
- W2 `G1 Dedicated Advantage + G2 Current Value`;
- W3 `Progress → Memory`.

### Kill implication

If a favourable one-tree test cannot create concrete advantage over the existing workaround:

- Growth must not scale discovery;
- Brand must not rescue the thesis with Continuity, Journey or Story;
- “easy logging” alone is insufficient differentiation;
- consumer workflow economics become materially weaker.

This is currently the most important participant-dependent gate in the project.

W1 materially sharpened the Growth entry map. The supported behaviours are not all the same type.

|---|---|---|---|

## 7. Candidate loop portfolio

### `L1 · First-Tree Inception`

**Current status:** `UNVALIDATED`

`first tree → simple record start → immediate Progress/Memory value → real event → voluntary return`

**Why it survives:** low migration by construction; aligns with Progress + Psychological Safety.

**Brand boundary:** no authority-heavy “we keep your tree safe” claim. Reassurance means “it is legitimate to be learning”, not horticultural safety.

**Key unknown:** whether a beginner wants record/progression enough when guidance may be the more urgent job.

---

### `L2 · One-Tree Land-and-Expand`

**Current status:** `UNVALIDATED · PRIMARY PARTICIPANT GATE`

`existing workflow pain → one real tree → immediate differentiated value → voluntary return → voluntary second-tree/real workflow shift`

**Why it matters:** directly tests whether value can arrive before full-collection migration.

**Key unknowns:** W4 G0/G1/G2; W2 Dedicated Advantage + Current Value.

**Kill condition:** no concrete one-tree advantage over Photos/Excel/notes under favourable conditions.

---

### `L3 · Progression Artifact`

**Current status:** `PARTIALLY SUPPORTED / PROPAGATION UNVALIDATED`

`fragmented history → coherent progression artifact → owner value → artifact travels → recipient activates → recipient may create/follow/contribute`

**Supported:** progression/photo-history value.

**Unvalidated:** natural travel, recipient activation, contribution.

**Brand rules:** `progress/story > prestige`; `contribution ≠ invitation for critique`; no follower/status dependency.

---

### `L4 · Comparable Journey`

**Current status:** `MIXED · DENSITY RISK HIGH` for L4-A; `L4-B` gated.

`need/problem/new species → comparable documented journey → descriptive learning → return/contribution → richer corpus`

**Current evidence:** progression records contain many needed matching fields; Tier 2 matching worked in the first corpus. Tier 1 could not be tested because the corpus was single-source / effectively single-climate.

**Meaning:** “learning from documented experience”, not “evidence says you should do X”.

**Next:** extend L4-A with multi-source/multi-climate cases before user-utility testing.

---

### `L5 · Teacher / Club Continuity`

**Current status:** `UNVALIDATED`

`teacher/club session → work/event recorded → student returns with same tree → authority/attestation remains with actor → actor repeats with future students`

**Why it survives:** recurring small-group learning is observed; could create distribution + retention evidence + attestation evidence.

**Constraints:** teacher as distributor ≠ payer; professional discovery can run early, but L5 Growth validation waits for user-level value. Kill if teacher/student becomes a data-entry clerk.

---

### `L6 · Transfer / Provenance`

**Current status:** `UNVALIDATED · STRATEGIC SECONDARY`

`steward A → tree + history → steward B → continuation → future transfer`

**Why it survives:** provenance/transfer have real cultural and product precedent.

**Why it is secondary:** long cycle, depends on accumulated history, transferability already exists competitively.

**Brand boundary:** evidence/attestation increases confidence in a claim, not status or quality of the tree.

## 8. Cross-loop prerequisites and kill conditions

### 8.1 Migration/logging kill map

A loop is structurally weak if it requires:

> **“do significant work now; receive differentiated value months later.”**

This particularly threatens:

- full-collection acquisition;
- Progression reconstruction;
- Comparable Journey contribution;
- teacher/club logging;
- provenance continuity;
- outcome-data flywheels.

### 8.2 Brand/trust kill conditions

Downgrade or kill a loop if:

A. it only works with unearned expert/care authority;  
B. it requires ranking/status/prestige to make artifacts travel;  
C. Continuity depends on promises the venture cannot operationally guarantee;  
D. “easy logging” is the only differentiation from Photos/Excel/notes;  
E. artifact travel depends on forced/incentivized sharing rather than recipient value;  
F. Comparable Journey only works as recommendation rather than descriptive learning;  
G. practitioner authority must be appropriated by the platform.

### 8.3 Economic kill discipline

- Manual/concierge labour is a real cost.
- Partner distribution is not free merely because there is no media spend.
- A mechanism is judged against the named ambition, currently S1.
- S3 aspiration cannot rescue weak S1 economics.

## 11. Competitive/distribution implications

The current registry holds **at least 45 known competitive bonsai software products/surfaces** as a discovered lower bound, not a census.

Current distribution evidence relevant to W4:

- 23 Apple measurement-eligible products in the cited iOS teardown;
- 16/23 (69%) with zero US ratings;
- top three hold 96% of 376 observed ratings;
- 17/23 launched in 2026;
- 20/23 updated in 2026;
- at least four known Android products are in the 10K+ install bracket;
- Mirai Mobile holds 379 ratings but is bundled with an existing membership/audience.

### W4 interpretation

1. The market is **crowded**, not empty.
2. Many maintained products appear to have weak observable discovery/attention.
3. Existing audience can materially improve distribution.
4. None of that proves retained value, conversion or viable economics.

Therefore W4 must not respond to category crowding with “more channels”. It must first validate a mechanism worth distributing.

## 18. Landing page — current W4 disposition

W4 now considers there to be enough reconciled material to create a **landing page focused on the proposed Bonsai web-app experience**, provided it is treated as:

> **Pre-MVP Acquisition & Message Validation Landing Page**

and **not** as:

> product launch site / proof that P1 was selected / proof of PMF / proof of a Growth loop.

### 18.1 What it may test

- which entry/problem framing generates meaningful action;
- Progress vs Memory vs Organization vs First-Tree framing;
- whether Psychological Safety reduces initial resistance;
- whether a dedicated-tree proposition attracts people currently using substitutes;
- segment differences;
- willingness to request access / join an actual test.

### 18.2 What it cannot validate

- L2 current differentiated value;
- repeat behaviour;
- migration tolerance;
- retention;
- willingness to pay;
- Comparable Journey utility;
- teacher/nursery distribution;
- virality/network effects;
- product-market fit.

### 18.3 Growth architecture for the landing page

Recommended narrative sequence:

1. **Progress** — concrete entry/value territory.
2. **Immediate one-tree value** — coherent photos/events/context.
3. **Memory** — retrieve what happened and see change.
4. **Continuity** — carefully framed as user-controlled/durable history, without permanence claims.
5. **Comparable Journey preview** — descriptive learning from documented cases, explicitly not advice.
6. **Psychological Safety** — no expert status or perfect tree required.
7. **CTA that can bridge to behaviour** — ideally “try with one tree” / request early access to a one-tree test, rather than a vanity waitlist only.

### 18.4 Evidence ladder

From weakest to strongest:

`page view → scroll → CTA click → email/access request → scheduling/accepting a test → actually trying one real tree`

The landing page is valuable precisely if it can feed the next behavioural gate rather than produce a decorative email count.

### 18.5 Form factor

Representing the prospective experience as a **mobile-first web app, responsive for tablet and desktop**, is compatible with Growth validation because many moments occur beside the tree, while review/collection/teacher workflows may benefit from larger screens.

This is **not** a technology-stack commitment.
