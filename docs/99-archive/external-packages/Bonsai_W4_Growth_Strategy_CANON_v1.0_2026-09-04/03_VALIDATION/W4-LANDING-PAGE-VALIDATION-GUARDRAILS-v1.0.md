# W4 · Landing Page Validation Guardrails v1.0

**Current W4 disposition:** proceed is strategically justified **as a validation instrument**.

## 1. Role

The landing page should be labelled internally as:

> **Pre-MVP Acquisition & Message Validation Landing Page**

It is not a launch website and does not select P1/P2/P3.

## 2. Primary questions

1. Which entry framing causes a relevant visitor to take a meaningful next step?
2. Does `Progress` outperform or complement `Memory`, `Organization` and `First Tree` framings?
3. Does a one-tree proposition reduce perceived migration burden?
4. Does Psychological Safety alter behaviour for beginners?
5. Can the page recruit people into the real L2 test rather than only collect emails?

## 3. Recommended message architecture

### Hero — Progress

Concrete, observable benefit around seeing one tree change over time.

### Immediate value

Photos + events + interventions + context in one coherent tree journey.

### Memory

Retrieve what happened, when it happened and how the tree changed.

### Continuity

Frame as user-controlled/durable history. Do not use promises the operation cannot guarantee.

### Comparable Journey preview

Present as:

> learning from documented comparable cases

not:

> recommendations / AI advice / “the evidence says do X”.

### Psychological Safety

No requirement to be expert, own a prestigious tree, or expose the tree for critique.

### CTA

Prefer a CTA capable of feeding behavioural validation:

- request early access;
- join a one-tree test;
- try with one tree when available.

A pure vanity waitlist is weaker evidence.

## 4. Candidate entry variants

- **A · Progress:** see your tree change over time.
- **B · Memory:** remember what happened and when.
- **C · Organization:** keep one coherent history for each tree.
- **D · First Tree:** start the history of your first bonsai from day one.

These are hypotheses, not final positioning.

## 5. Evidence ladder

| Behaviour | Evidence strength for acquisition intent |
|---|---|
| page view / impression | very weak |
| scroll / section engagement | weak |
| CTA click | weak–moderate |
| email / access request | moderate intention, still cheap |
| scheduling / accepting test participation | stronger |
| using one real tree | behavioural evidence; enters L2 territory |

Do not report a click-through rate as product demand.

## 6. What must not appear as current promise

- “we tell you exactly what to do”;
- “avoid killing your bonsai”;
- AI/expert advice claims;
- expert-led authority owned by the platform;
- “forever”, “permanent”, “never lose”, “lifetime record”;
- generic community/feed as core value;
- ranking, prestige, pedigree or follower mechanics;
- “verified tree”;
- full-collection migration as the default first task.

## 7. Form factor

A **mobile-first web-app concept**, responsive for tablet and desktop, is compatible with the Growth hypothesis:

- mobile fits purchase, photography, workshop and beside-the-tree moments;
- tablet/desktop may fit collection review, history and teacher workflows.

This is a validation-oriented experience assumption, not a stack decision.

## 8. Landing-page kill interpretation

A weak landing result may kill a message, not necessarily the underlying mechanism.

A strong landing result may justify recruitment/testing, not product build.

The decisive value gate remains L2.
